
- Decision: model trigger lifecycle metadata as a nested `runtime.trigger_runtime` contract on `PluginRuntimeConfig` variants so manifest remains the sole business schema source and decode paths do not introduce shadow runtime configuration.
- Decision: keep `trigger_runtime` fields optional in decode shape and enforce required semantics in `PluginManifest::validate` to guarantee stable `ContractError` mapping instead of raw TOML decode failures for missing lifecycle semantics.
- Decision: enforce lifecycle/runtime pairing (`process` => `process_short_lived`, `wasm_component` => `wasm_daemon_persistent_session`) plus lifecycle-specific push callback and durable ACK semantics to reject ambiguous mixed declarations early.
- Decision: require typed host error categories to include `transport`, `protocol_contract`, and `plugin_fatal` for all external trigger runtime contracts.
- Decision: keep Task 3 supervisor scope narrow to in-memory registry/state and reconcile seams keyed by `trigger_id`; durable callback transport, wasm store ownership, and process convergence remain deferred to later tasks.
- Decision: model the Task 4 transport cut with explicit WIT callback result classes (`result<host-push-success, host-push-error>`) and keep only transport envelope bytes in WIT so manifest contracts remain the sole business schema source.
- Decision: keep `WasmTriggerSession` as a trigger_wasm-owned runtime type but instantiate and retain it only from `ExternalTriggerSupervisor`, with `ExternalTriggerSession` owning `Option<WasmTriggerSession>`; this preserves daemon boundary ownership while avoiding any `TriggerPlane` lifetime coupling.
- Decision: converge process runtime orchestration under the same supervisor/session boundary as wasm by staging process plugin emissions before acceptance, rather than allowing `TriggerPlane` to own process listener orchestration.
- Decision: preserve existing acceptance/replay semantics by introducing an explicit acceptance-only `TriggerPlane` constructor for daemon turns, so all accepted-event writes still flow through one normalization path.
- Decision: enforce bounded long-lived wasm runtime growth with explicit store limiter config (`WasmTriggerSessionConfig.store_limiter`) owned at session-construction time, and keep defaults centralized in `trigger_wasm.rs` to avoid implicit unbounded store behavior.
- Decision: place fairness control at the supervisor/session boundary with explicit per-cycle budgets and deterministic round-robin session selection, then map session budget exhaustion onto existing `BudgetExhausted -> RetryableBackpressure` callback outcomes rather than introducing a new push result family.
- Decision: for Task-13 matrix closure, prioritize deterministic assertions on persisted state transitions (pending/accepted staged rows, trigger-record cardinality, stable round-robin picks) over wall-clock stress loops, so fairness/recovery coverage remains reproducible across CI and local runs.
